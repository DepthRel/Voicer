# Архитектура Voicer

[English](../En/Architecture.md) · [Deutsch](../De/Architecture.md) · [Español](../Es/Architecture.md) · [Français](../Fr/Architecture.md) · [Português](../Pt/Architecture.md) · **Русский**

Voicer превращает речь из аудио- и видеофайлов в текст, а текст — в речь, на компьютере пользователя. Вкладки —
«Транскрибация», «Генерация», «История» и «Настройки».

## Проекты

| Проект | Отвечает за |
|---|---|
| `Sources/Core/Voicer.Localization` | языковые пакеты (`Languages/<code>.json`), `ILocalizer`, `LocalizedError` |
| `Sources/Core/Voicer.Core` | папки данных (`AppPaths`), каталог моделей и их хранилище, вычислительные устройства, транскрипты и их экспорт в Markdown, история распознаваний (`ITranscriptHistory`), медиаформаты, протокол рабочего процесса |
| `Sources/Infrastructure/Voicer.Downloads` | загрузки по HTTPS с докачкой и проверкой размера и SHA-256; установка моделей |
| `Sources/Infrastructure/Voicer.Media` | FFmpeg: поиск, установка закреплённой сборки в Windows, извлечение звука любого файла в WAV 16 кГц моно, сжатие его в Opus для истории, декодирование сохранённого звука для проигрывателя |
| `Sources/Infrastructure/Voicer.Storage` | база данных папки данных (SQLite, `Data/voicer.db`): история распознаваний и их звук |
| `Sources/Infrastructure/Voicer.LanguageModels` | клиент серверов языковых моделей с OpenAI-совместимым API (LM Studio, Ollama, llama.cpp, Jan): список моделей, потоковые ответы |
| `Sources/Infrastructure/Voicer.Audio` | проигрыватель сохранённого звука: `AudioPlayer` поверх декодера FFmpeg и звукового устройства (OpenAL Soft) |
| `Sources/Speech/Voicer.Speech.Whisper` | Whisper через Whisper.net: список устройств, распознавание, хост рабочего процесса |
| `Sources/Speech/Voicer.Speech.Llama` | текст в речь через llama.cpp: его закреплённая сборка и установка, аргументы llama-tts и синтезатор, который запускает его на каждый фрагмент текста; llama-server моделей Voicer (`LlamaModelServer`): поиска по смыслу (`LlamaEmbeddingServer`) и резюме (`LlamaChatServer`), их состояние и остановка |
| `Sources/Apps/Voicer.UI` | приложение на Avalonia (MVVM на CommunityToolkit.Mvvm); та же программа — рабочий процесс |
| `Sources/Apps/Voicer.Pages` | страница проекта: статические файлы, которые публикует GitHub Pages |

Зависимости направлены внутрь: ядро не знает ни UI, ни сети, ни движка.

## Распознавание

```
файл (mp3, mp4, mkv, …)
  └─ FfmpegAudioExtractor ── ffmpeg ──► Data/Temp/<guid>.wav (16 кГц, моно, 16 бит)
       └─ ProcessWorkerClient ── Voicer.UI --worker --parent <pid> transcribe --model … --audio … --device <n>
            └─ WorkerHost ─ WhisperSpeechEngine (Whisper.net, whisper.cpp)
                 stdout: по объекту JSON в строке: ModelLoaded, Progress, Segment…, Done | Error
       ◄─ Transcript (фрагменты, определённый язык) ── WAV удаляется
```

`TranscriptionRunner` ведёт шаги; `TranscriptionViewModel` показывает этап и прогресс, сохраняет текст в историю и
открывает его в окне записи, которое читает текст обратно из базы и экспортирует его в Markdown
(`MarkdownTranscriptWriter`).

`WhisperSpeechEngine` декодирует каждое 30-секундное окно звука само по себе (`n_max_text_ctx = 0`). По умолчанию
whisper.cpp подаёт каждому окну текст предыдущих как подсказку, а `no_context` очищает этот текст только перед первым
окном: фраза, которую модель однажды повторила или придумала на тишине, возвращается в каждом следующем окне до конца
длинного файла и вытесняет настоящую речь. Окна декодируются лучевым поиском ширины 5, как в `whisper-cli`, с
переходом на более высокую температуру (шаг 0,2) для окна, которое вышло повторяющимся (энтропия ниже 2,4) или
неуверенным (средний логарифм вероятности ниже -1). `RepetitionGuard` отбрасывает фрагмент из трёх и более слов,
дословно повторяющий один из трёх последних.

Перед моделью детектор речи находит, где говорят: Silero VAD 6.2.0 в формате ggml (`SpeechDetectorModel`, 0,9 МБ,
закреплён, как любая загрузка, хранится в `Data/Models/silero-vad`), его запускает whisper.cpp на процессоре.
`SpeechMap` склеивает участки речи с паузами по 0,3 с, модель распознаёт только их, а время каждого фрагмента
пересчитывается обратно во время файла. Тишина, музыка и шум не доходят до модели, поэтому она ничего для них не
выдумывает (на тишине Whisper пишет «Спасибо.»), а долгая пауза не стоит времени. Файл без речи даёт пустой текст.
Детектор скачивается вместе с первой моделью Whisper; модель, скачанная раньше, получает его при первом распознавании
(`SpeechDetectorSource`). Если скачать его не удалось, распознаётся весь звук, и страница об этом сообщает.

## Зачем отдельный процесс

whisper.cpp работает в нативном коде, на драйверах видеокарты. Сбой драйвера (на машине разработки встроенная AMD
падает внутри Vulkan при загрузке модели) завершает весь процесс. Поэтому движок никогда не работает в окне: программа
запускает саму себя с `--worker` на каждую команду, читает её JSON-строки и превращает сбой в сообщение
(`WorkerSession`). Рабочий процесс следит за процессом, переданным в `--parent`, и останавливается вместе с
приложением. Отмена распознавания сразу завершает рабочий процесс.

## Устройства

`GgmlDeviceProbe` спрашивает у библиотеки ggml загруженного Whisper.net рантайма её устройства (`ggml_backend_dev_*`)
со свободной и общей памятью. whisper.cpp нумерует видеокарты (дискретные и встроенные) в порядке этого реестра, поэтому
показанный индекс — ровно тот `GpuDevice`, который берёт движок; процессор — `-1`. Рантаймы: процессорный (с Metal на
Apple Silicon) и Vulkan (Windows и Linux, любая видеокарта). По умолчанию выбирается дискретная видеокарта, затем
встроенная, затем процессор. Если рабочий процесс не смог перечислить устройства, предлагается только процессор.

## Модели и инструменты

Каталог (`SpeechModelCatalog`) содержит проверенные многоязычные модели Whisper в файлах ggml от whisper.cpp, от самой
тяжёлой к самой лёгкой: large-v3, large-v3-turbo, medium и small (tiny и base слишком теряют в точности). Каждая модель
есть в тех квантованиях, которые для неё публикует whisper.cpp (`ModelQuantization`): F16 (полная точность), Q8 и Q5;
у large-v3 нет Q8. Каждый файл закреплён размером и SHA-256. В настройках у каждой модели своя карточка с выбором
квантования; файл скачивается в папку своего семейства, `Data/Models/<семейство>`, поэтому несколько квантований одной
модели лежат рядом, а распознавание показывает каждый скачанный файл как `<имя> <квантование>`. Полученная часть ждёт
в `<файл>.part`, поэтому прерванная загрузка продолжается, а файл используется только после совпадения контрольной
суммы. FFmpeg в Windows ставится так же (сборка Gyan 9.0.2 essentials в `Data/Tools/FFmpeg`); Linux и macOS используют
системный FFmpeg, который ищется в `PATH` и в обычных местах менеджеров пакетов.

Настройки не загромождены моделями: строка каталога сообщает, сколько моделей получено, а её кнопка открывает окно с
карточкой на каждую модель (`ModelCatalogViewModel`, `ModelsWindow`). У скачанной модели карточка подсвечена и помечена
как полученная; модель, которая хорошо работает на одном процессоре (Whisper Small, Kokoro), показывает это как
преимущество. Модели голоса и llama.cpp описаны в разделе [Генерация голоса](#генерация-голоса).

## История

Каждый распознанный текст попадает в базу SQLite папки данных, `Data/voicer.db` (`SqliteTranscriptHistory` через
Microsoft.Data.Sqlite): строка `records` на каждое распознавание (файл, модель, устройство, язык, время со смещением от
UTC, длительность, начало текста) и её фрагменты в `segments`. Версия схемы хранится в `PRAGMA user_version`; файл
более новой версии не открывается. Запись знает, как она получена (`kind`, версия схемы 5): распознавание или
сгенерированная речь; вкладка «История» помечает так каждую запись. Вкладка «История» показывает записи, новые сверху; запись открывается в своём окне,
прочитанная из базы, и удаляется после подтверждения. Удаление физическое: `secure_delete` затирает удалённые строки, а
`auto_vacuum = INCREMENTAL` возвращает освободившиеся страницы файловой системе, так что текста в файле больше нет.
Хранилище сообщает о сбоях как `IOException` с локализованным текстом; страницы их показывают.

После распознавания `RecordKeeper` сжимает первую звуковую дорожку файла через FFmpeg в Opus (моно, 48 кГц, 32 кбит/с,
около 14 МБ в час, `Data/Temp/Audio`) и сохраняет её вместе с текстом одной транзакцией: таблица `audio` (версия схемы
2), запись и чтение потоком через `SqliteBlob`, никогда целиком в памяти. Если звук сжать не удалось (например, в
системном FFmpeg нет `libopus`), текст сохраняется без него, а страница об этом сообщает. Длительность записи со звуком
— длительность звука.

В окне записи сверху проигрыватель, ниже текст. `RecordViewer` на время, пока окно открыто, выгружает звук во временный
файл. `AudioPlayer` запускает FFmpeg (`FfmpegPcmDecoder`) с выбранного момента на выбранной скорости (фильтр `atempo`
сохраняет высоту голоса; от вдвое медленнее до вдвое быстрее) и подаёт сырые отсчёты (16 бит, моно, 48 кГц) в OpenAL Soft
(`OpenAlOutput`: источник с четырьмя буферами по 100 мс); нужные функции объявлены в `OpenAlNative`, нативная библиотека
приходит из пакета `Silk.NET.OpenAL.Soft.Native`. Перемотка или новая скорость начинают новый прогон декодера; позиция —
начало прогона плюс сыгранное устройством, умноженное на скорость. Кнопки перематывают на десять секунд назад и вперёд;
ползунок применяется при следующем обновлении окна (пять раз в секунду), поэтому перетаскивание не запускает FFmpeg на
каждый пиксель.

Пока звучит запись, звучащая фраза подсвечена в тексте и остаётся на виду (`TranscriptLayout`; окно следит за плеером
пять раз в секунду и прокручивает текст, только когда фраза уходит из видимой части). Текст распознавания можно
исправить через меню текста: слово или выделение пишется заново или удаляется, звук на это время встаёт на паузу.
Распознанные фрагменты в `segments` не меняются никогда: исправление — строка `corrections` (версия схемы 6: фраза,
место и длина в её обрезанном тексте, распознанный кусок, замена, время), которая лежит поверх них
(`TranscriptCorrections`, Core). Исправление поверх другого сливается с ним, так что распознанным куском остаётся текст
Whisper; если вернуть исходное, исправление пропадает, а строка, которая больше не сходится с текстом, пропускается.
Исправленное место подчёркнуто и подсказывает, что там было распознано; меню возвращает исходное. Сохранение
исправлений в той же транзакции заново пишет фрагменты поиска записи и начало её текста в списке; векторы новых
фрагментов досчитывает следующий поиск. Экспорт, новое резюме и вопросы берут исправленный текст; сгенерированная речь —
это то, что произнесено, и не исправляется.

## Резюме

Резюме пишет языковая модель на сервере, который запускает сам пользователь: LM Studio, Ollama, llama.cpp
(`llama-server`), Jan или любой другой с OpenAI-совместимым API. В настройках хранятся его адрес, необязательный ключ,
модель и контекст, с которым она загружена (`summary.*` в `Data/settings.json`); модели перечисляются запросом
`GET models`. Модели распознавания к этому времени в памяти нет: её рабочий процесс завершился вместе с распознаванием.

`Summarizer` (ядро) подгоняет текст под контекст: помещающийся текст резюмируется одним запросом; более длинный
`TextChunker` режет (по строкам, затем предложениям, затем словам) на части из расчёта около 2,5 символа на токен, по
каждой части модель пишет заметки, а заметки сводятся в резюме (если вместе они не помещаются — сначала сводятся
группами, не больше трёх кругов). Инструкции берутся из языкового пакета (`Summary.Prompt.*`), поэтому резюме пишется на
языке интерфейса. `ReasoningFilter` убирает `<think>…</think>` «думающих» моделей. `OpenAiCompatibleClient` получает
ответ потоком (`stream: true`, server-sent events; сервер, отвечающий целиком, тоже понимается) и формулирует сбои:
сервер не отвечает, отказ с кодом и сообщением, ответ невозможно прочитать.

Резюме хранится вместе с записью (`summaries`, версия схемы 3: текст, модель, время), новое заменяет прежнее; удаляется
вместе с записью. Страница «Транскрибация» после распознавания предлагает «Резюмирование текста» и по готовности
открывает окно записи; окно показывает резюме под текстом, составляет его (заново) и выводит по мере поступления.
Экспорт в Markdown ставит резюме перед текстом.

Настройки хранят один выбор того, что пишет резюме и ответы (`ModelSource`, ключ `summary.source`): выключено, лёгкая
модель Voicer или модель сервера. Подключение к серверу (адрес, ключ и список моделей) вынесено в отдельный раздел,
общий для резюме и поиска. Модели Voicer: Qwen3-4B-Instruct-2507 и Qwen3-1.7B (Apache-2.0, GGUF Q4_K_M, около ста
языков); они слабее полноценной модели сервера, и настройки об этом предупреждают. Первая установленная работает в
`llama-server` закреплённой сборки (`LlamaChatServer`), как модель поиска: только на 127.0.0.1, на свободном порту, со
случайным ключом, один слот с контекстом 8192 токена; `--reasoning-budget 0` не даёт Qwen3-1.7B рассуждать вслух.
`ChatModelSource` открывает сессию на резюме или вопрос и держит сервер, пока она не закончится. Каждая модель Voicer в
памяти видна в полосе вкладок на любой странице вместе с занятой памятью и кнопкой, которая сразу её выгружает, даже
во время работы: эта работа завершается сообщением, что модель выгружена, а следующий запрос запускает её снова.
Модель Voicer, чей источник больше не выбран, тоже выгружается.

## Поиск и вопросы

Вкладка «История» ищет по записям и отвечает на вопросы о них (`Core/Search`). При сохранении записи её фрагменты
собираются в абзацы примерно по 600 символов с их моментами (`PassageBuilder`): это единица, которую находит поиск,
читает модель и на которую перематывает проигрыватель (версия схемы 4: `passages`; записи, сохранённые раньше,
индексирует переход на новую схему).

- **По словам**: индекс FTS5 `passages_fts` (`unicode61`, без диакритики, ранжирование BM25). `FullTextQuery`
  превращает введённое в безопасный запрос: слова в кавычках — фраза; остальные слова ищутся по началу без последней
  одной-двух букв, поэтому находятся и другие формы (*договоров* находит *договор*); достаточно любого слова, больше
  совпавших — выше в выдаче. В индекс попадают только буквы и цифры.
- **По смыслу**: модель эмбеддингов на том же сервере (`POST embeddings`), выбирается в настройках рядом с моделью
  резюме; для речи не на английском — многоязычная (bge-m3, multilingual-e5). Перед поиском каждый абзац без вектора
  этой модели его получает, по шестнадцать за запрос (индексация показывается); векторы нормализуются и хранятся по
  моделям в `embeddings`, так что смена модели индексирует заново, не теряя старых. Ближайшие находятся по косинусу в
  памяти: тысячи абзацев — миллисекунды, нативное расширение не нужно. `EmbeddingText` добавляет префиксы, которых ждут
  некоторые семейства (`query:`/`passage:` у e5, `search_query:`/`search_document:` у nomic).
  Модель может быть своей: bge-m3 (MIT), скачанная в настройках и запущенная `llama-server` той же закреплённой
  сборки (`LlamaEmbeddingServer`): только на 127.0.0.1, на свободном порту, со случайным ключом. Её запускает первый
  поиск, каждый запрос удерживает её, а останавливается она через пять минут без запросов, по кнопке в настройках и
  вместе с приложением. Настройки показывают её состояние, память и долю процессора её процесса.
  Раздел настроек «Модели поиска по истории» хранит один выбор источника (`ModelSource`, ключ `search.source`): выключен,
  своя модель Voicer или модель эмбеддингов сервера. Выбор, который ещё не готов (модель не скачана, нет llama.cpp,
  модель сервера не выбрана), ищет по словам и объясняет почему. До первого выбора источник следует установленному.
  Когда источник — сервер, его проверка в настройках просит у выбранной модели один вектор, поэтому ошибочно
  выбранная чат-модель видна сразу там (LM Studio отвечает на неё обманчивым «No models loaded»).
- **Слияние**: оба списка объединяются методом Reciprocal Rank Fusion (k = 60), как гибридный поиск Elasticsearch.
  Без модели эмбеддингов поиск идёт только по словам.
- **Подсветка**: в найденном абзаце слова запроса выделены жирным на акцентном фоне. Совпадения ищутся по тем же
  началам слов, что и в индексе (`SearchMarks`); если первое совпадение далеко от начала, абзац показывается с него.
  Запись, открытая из поиска, прокручивается к абзацу, показывает его на акцентном фоне и играет с его начала.
- **Вопросы** (генерация с извлечением, `RecordQuestions`): лучшие абзацы, помещающиеся в контекст, передаются модели
  резюме с номерами, файлом, датой и временем; инструкции языкового пакета велят отвечать только по ним и ссылаться
  как [1], [2]. Ответ выводится по мере поступления, источники — под ним. Если ничего не найдено, запроса к модели нет.

Найденный абзац открывает свою запись с проигрывателем на начале абзаца. Абзацы, их индекс (FTS5 `secure-delete`) и
векторы удаляются вместе с записью и не остаются в файле.

Некоторые серверы кладут весь ответ модели в `reasoning_content`, если модель так и не закрыла рассуждение;
`OpenAiCompatibleClient` тогда берёт его, а не возвращает пустоту.

## Генерация голоса

Вкладка «Генерация» озвучивает текст свободной моделью голоса на этом компьютере — вплоть до озвучки на десятки минут.
Модели (`VoiceModelCatalog`) — файлы GGUF, которые проект llama.cpp сам конвертирует и публикует (ggml-org на Hugging
Face); каждый закреплён размером и SHA-256 на фиксированной ревизии своего репозитория: Qwen3-TTS 1.7B Base (Apache-2.0,
десять языков, голос по образцу), Chatterbox Turbo (MIT, английский, встроенный голос или образец), Kokoro 82M
(Apache-2.0, английский, 28 готовых голосов, быстро работает на процессоре) и Chatterbox Multilingual (MIT, 23 языка).
Модель — это два файла, веса и проектор (`mmproj`: аудиокодек, голоса, кодировщик голоса), они скачиваются в
`Data/Models/<id>`.

Запускает их llama.cpp (MIT). Приложение ставит один закреплённый выпуск (`LlamaCppPackage`) в
`Data/Tools/LlamaCpp/<выпуск>`: сборку с Vulkan в Windows и Linux x64, сборку с Metal в macOS arm64; архив
распаковывается в сторону, каждая запись проверяется на то, что не выходит за папку, и ставится на место целиком.
Системный llama.cpp не берётся: моделям нужен тот выпуск, с которым они проверены.

```
текст
  └─ SpeechScript: строка — абзац, абзац режется между предложениями на фрагменты до 250 символов
       ├─ образец (необязательно): FfmpegVoiceSampleExtractor ── первые 30 с, моно, WAV 24 кГц
       └─ на каждый фрагмент: LlamaTtsSynthesizer ── llama-tts -m … -mm … -p <фрагмент> --output part-N.wav
                     [--tts-lang] [--tts-voice] [--tts-speaker-file] [--device VulkanN | none]
  └─ WaveJoiner: отсчёты копируются как есть, 250 мс тишины между предложениями, 650 мс между абзацами
       ◄─ Data/Temp/Generation/<guid>/<первые слова>.wav + фрагмент текста на каждый кусок со своим временем
```

Каждый фрагмент озвучивает отдельный процесс, запущенный без оболочки: модель загружается, говорит и уходит из памяти
вместе с процессом, поэтому после генерации от неё ничего не остаётся, а нативный сбой видеодрайвера завершает только
этот процесс; о сбое сообщают последние строки его журнала. Отмена сразу завершает процесс и удаляет папку генерации.
Устройство — то же, что у распознавания: номер видеокарты среди GPU ggml и есть `VulkanN` у llama.cpp; процессору
передаётся `--device none -ngl 0`; в macOS Metal выбирает устройство сам.

Результат проигрывается прямо на странице (плеер истории) и сохраняется в WAV туда, куда укажет пользователь; в историю
он попадает так же, как распознавание, со звуком в Opus, с пометкой «генерация». Модель, язык, голос и образец последней
генерации запоминаются (`generation.*` в `Data/settings.json`), так что серия записей звучит одним голосом.

## Папка данных

`AppPaths` выбирает папку данных: `--data <папка>`; иначе `Data` рядом с маркером `voicer.portable` пакета; иначе
`Data` рядом с программой; а если туда нельзя писать (Program Files, `/opt`) — профиль пользователя
(`%LOCALAPPDATA%\Voicer\Data`, `~/.local/share/Voicer/Data`).

Непредвиденный сбой окна не завершает приложение: `App` перехватывает его в диспетчере, записывает в
`Data/errors.log` (`ErrorLog`: время, тип, сообщение и стек; после 1 МБ файл начинается заново) и показывает
уведомление с путём к журналу, не больше одного за раз.

## Интерфейс

Одна тёмная тема: палитра RCynQ с бо́льшим свечением — акцент светится вокруг основных кнопок, выбранной вкладки,
индикаторов прогресса и файла, перетаскиваемого на область. Язык выбирается при первом запуске по языку системы и
запоминается; переключение сразу переводит все экраны (`LocalizationSource`, `LocalizedViewModel`).
